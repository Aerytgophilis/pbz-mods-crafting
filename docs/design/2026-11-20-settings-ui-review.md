# 设置项、预设与 GUI：Opus + Gemini Neon 双路评审与合并方案（2026-11-20）

题目：`.agent-runs/tasks/settings-ui-review.md`（本地）。两位评审独立作答：Opus 5.5 子代理（可上网核实 Mods Menu），Gemini 4 Neon（`gemini-ask.ps1`，只读，附带 mod README、头脑风暴、发布规划）。

## 1. 两边一致的结论

- **要预设，3 个**，加“自定义”状态。
- **v0.1 只用 `config.json` + Alt+F5**，零依赖先发布。
- **不做自研游戏内面板（UMG）**：成本高，游戏一更新就容易坏。**不做游戏外配置工具**：多一步，多一样要维护。
- **Mods Menu 推迟到 v0.2 再评估**。
- **不硬禁极端组合**（单机游戏，玩家自己选），改为数值钳制 + 警告。
- **砍掉**：花数量上限滑块（25 朵是天然的节流阀）、`extraBigFlowers`（已定全部留大花）。
- **不暴露给玩家、实测后写死**：`tickCoalesce`、前期间隔和前期杀气系数等调参项。

## 2. 分歧与裁决

| 议题 | Opus | Neon | 合并方案 | 理由 |
|---|---|---|---|---|
| 玩家可见项数量 | 4 项（预设、面积、寿命、音量），v0.2 再加两个开关 | 6 项（面积、寿命、间隔、音量、极、生生不息） | **6 项**：预设、面积、寿命、音量、生生不息开关、彼岸·极开关 | 两个开关是功能开关，玩家一看就懂；间隔是平衡参数，放进预设和高级项 |
| 寿命 60 s 档 | 降为高级项 | 保留 | **保留，但标注“高强度”** | 用户已确认过这个档位；60 s 在 25 朵上限下多半活不满，风险可控 |
| 自定义状态的判断 | `preset` + 可选覆盖键，加载时在日志里列出覆盖了哪些项 | 改任一单项就自动切到 custom | **采用 Opus 的做法** | 不用逐项比较数值，实现更简单，日志也直观 |
| 彼岸·极进不进预设 | 未列 | 三档都开 | “含苞”关，“盛放”和“花海”开 | 含苞定位是接近原版，极是满级强化 |
| Boss 单独倍率 | 砍 | 推迟 | **推迟** | 先看 Boss 实测数据 |
| 护栏 | 每朵花安全寿命上限 120 s；数值钳制；极端组合写日志警告；README 给预设标强度星级 | 同帧特效 / 音效并发上限；+200% 视野警告 | **全部采纳**，安全寿命上限需要用户确认（见下） | 防敌人卡在地形里让花永远不消失；防糊屏 |
| Mods Menu 成本 | 核实后认为偏高：它更像“配置文件编辑器 + 自带加载器”，用 .txt 配置，可能要作者逐个适配 | 前提是换入口能共存 | v0.2 先实测共存，再决定 | — |

**需要用户确认的一点**：用户把 Lv30 的生生不息定为“无上限”（敌人在花里时花不消失）。Opus 建议加一个 120 s 的安全寿命上限，防止敌人卡在地形里，导致花永远占着 25 朵的名额。合并方案默认 120 s，可在高级项里改成 0（真正无上限）。

## 3. 合并方案

### 3.1 预设

| | 含苞（接近原版，★） | **盛放（默认，★★）** | 花海（爽快，★★★） |
|---|---|---|---|
| 花丛面积 | 0 | +25% | +80% |
| 存在时间 | 15 s | 15 s | 25 s |
| 自动爆炸间隔 | 6 s | 4 s | 3 s |
| 自动爆炸伤害倍率 | 0.25 | 0.4 | 0.5 |
| 生生不息 | 关 | 开 | 开 |
| 彼岸·极 | 关 | 开 | 开 |

自动爆炸音量独立于预设，默认 25%。+200% 面积和 60 s 寿命不进任何预设，只能手动选。

### 3.2 玩家可见项（config.json 顶部，README 用表格说明）

1. `preset`：含苞 / 盛放 / 花海
2. `flowerAreaScale`：0 / +25% / +40% / +80% / +200%
3. `flowerLifetime`：15 / 25 / 60 s（60 s 标“高强度”）
4. `tickVolume`：0–100%，默认 25%
5. `lingerEnabled`：生生不息开关
6. `ultraEnabled`：彼岸·极开关
7. 另加零成本的总开关 `enabled`

### 3.3 高级项（只写在 config.json 下半部分，README 列表说明）

`tickInterval`、`tickDamageScale`、`manualCooldown`、`manualKeepsFlower`、`tickShake`、`extraWhiteFlowersLv25/30`、`whiteFlowerTargeting`、`lingerMaxLv15/Lv20`、`lingerSafetyCap`（默认 120 s，0 表示无上限）、`ultraAfterTicks`。

### 3.4 写死的常量（实测后定）

`tickCoalesce`、`tickIntervalEarly`、`earlyShachiScale`、`tickShachiSmall/Big`、`ultimateTickFactor`。

### 3.5 护栏

- 加载时把所有数值钳在合法范围内（例如间隔 ≥ 1.5 s，伤害倍率 ≤ 1.0），超出时写日志。
- 面积 ≥ +80% 且寿命 ≥ 25 s 时在日志里警告。
- 同一帧的自动爆炸特效、音效数量设上限。
- 每朵花的安全寿命上限 `lingerSafetyCap`（默认 120 s）。

### 3.6 待核实

- PBZModLoader 能不能解析带注释的 JSON（JSONC）。不能的话，用 `"_说明"` 字段加 README 参数表。
- Mods Menu 和我们的加载器入口能否共存，它有没有第三方注册设置项的接口。

## 4. 评审原文

### Opus 5.5

结论：v0.1 给玩家 1 个预设选择加 3 个单项（面积、存在时间 15/25、音量），全部放在 config.json，不做 GUI，Mods Menu 等核实清楚再说。高级项和写死项的划分、预设“含苞 / 盛放 / 花海”、`preset` + 覆盖键的共存方式、120 s 安全寿命上限、数值钳制和日志警告、README 星级，均见上文。Mods Menu 核实（来源：VGTimes 转载页）：游戏设置页里的 Mods 标签、F9 打开；原生滑块；直接编辑各作者的 .txt 配置并保留注释；11-13 版自带 JS 加载器，入口 hid.dll；“原生支持 15 个作者的 mod”。未找到第三方注册设置项的 API 或开发文档，推断它与 PBZModLoader 是并列关系，接入成本偏高。

### Gemini 4 Neon

结论：普通玩家暴露 6 项（v0.1 先 5 项）+ 3 预设；GUI 先纯 JSON，v0.2 接 Mods Menu；极端组合只加警告和底层护栏，不硬锁。暴露：面积、寿命、间隔（3/4/6 s）、音量（0/25/50/100%）、彼岸·极开关、生生不息开关（v0.2）。预设：克制（0% / 15 s / 6 s / 0.25 / 极开 / 生生不息关）、均衡（+25% / 15 s / 4 s / 0.4 / 开 / 开）、花海（+80% / 25 s / 3 s / 0.5 / 开 / 开）；改任一单项自动切 custom。拒绝自研 UMG 和外部工具。风险：+200% + 60 s + 生生不息无上限 + 3 s 会糊屏、遮挡弹反；加 +200% 视野警告和硬编码护栏（25 朵上限、合批、同帧特效 / 音效并发上限）。砍掉花上限滑块和 `extraBigFlowers`；推迟 Mods Menu、生生不息 / 断情（Lv15/20 标签未知）、聚花、吸血、Boss 单独倍率。
